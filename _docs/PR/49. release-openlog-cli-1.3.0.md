## 2. 변경 배경 및 목표
- **변경 전 상태:** `develop`에는 `openlog init`, MCP instructions, `start_openlog_session`이 포함돼 있지만 CLI package version과 npm `latest`는 모두 `1.2.1`입니다.
- **문제/필요성:** `npx -y @openloghq/cli@latest init`은 배포된 1.2.1을 실행하므로 새 명령을 인식하지 못하고, 배포된 MCP에서도 새 session Tool을 사용할 수 없습니다.
- **이번 PR의 목표:** CLI package version을 `1.3.0`으로 변경해 merge 후 npm 자동 배포 workflow가 새 CLI와 MCP 구현을 배포하도록 합니다.

---

## 3. 주요 구현 내용 및 동작 방식

### A. OpenLog CLI 1.3.0 릴리스 준비
- **관련 위치/대상:** `packages/openlog-cli/package.json`, `packages/openlog-cli/package-lock.json`
- **변경 전 상황:** package와 lockfile의 root version이 이미 배포된 `1.2.1`이었습니다.
- **변경한 내용:** 새 CLI 명령과 MCP 기능 추가를 반영해 package version을 SemVer minor release인 `1.3.0`으로 맞췄습니다.
- **변경 후 동작:** develop merge 시 CLI workflow가 npm에서 미배포 버전을 확인하고 `@openloghq/cli@1.3.0`을 publish합니다.
- **구현 흐름:**
  1. PR에서 CLI test, build, package contents를 검증합니다.
  2. merge 후 develop publish job이 `1.3.0`의 미배포 상태를 확인하고 npm publish를 실행합니다.
- **바뀌는 데이터/상태:** npm package version과 `latest` dist-tag가 배포 완료 후 `1.3.0`으로 변경됩니다.
- **영향 범위:** `npx @openloghq/cli@latest`, 전역 MCP 설정이 실행하는 OpenLog CLI/MCP 버전
