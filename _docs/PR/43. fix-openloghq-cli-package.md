## 2. 변경 배경 및 목표
- **변경 전 상태:** OpenLog CLI가 개인 npm scope의 `@kitae9999/openlog-cli`로 배포되고, README와 웹 MCP 가이드도 이 패키지명을 설치 명령과 설정 예시에 사용했다. 프런트엔드는 임시 텍스트 로고와 기본 Vercel 파비콘을 사용했다.
- **문제/필요성:** 공식 제품 CLI가 개인 계정 패키지명에 종속돼 있었고, 새로 확보한 OpenLog 조직 scope와 사용자 안내가 일치하지 않았다. 제품 화면과 브라우저 탭에도 확정된 OpenLog 브랜드 자산이 반영되지 않았다.
- **이번 PR의 목표:** CLI 패키지 식별자를 `@openloghq/cli`로 통일하고, 설치·로그인·MCP 실행 경로와 npm 링크가 새 공개 패키지를 가리키게 한다. 동시에 OpenLog 워드마크와 마크를 공통 컴포넌트로 적용하고 기본 Vercel 파비콘을 교체한다.

---

## 3. 주요 구현 내용 및 동작 방식

### A. CLI 패키지 식별자 변경
- **관련 위치/대상:** `packages/openlog-cli/package.json`, `packages/openlog-cli/package-lock.json`
- **변경 전 상황:** npm package name이 `@kitae9999/openlog-cli`로 설정돼 있었다.
- **변경한 내용:** package name과 lockfile의 루트 package name을 `@openloghq/cli`로 변경했다.
- **변경 후 동작:** `npm install -g @openloghq/cli` 또는 `npx -y @openloghq/cli`로 CLI를 설치·실행할 수 있다. 실행 명령 `openlog`와 Node.js 20 이상 요구사항은 유지된다.
- **바뀌는 데이터/상태:** npm 패키지 식별자가 `@openloghq/cli@1.1.0`으로 변경되고 `latest` tag가 `1.1.0`을 가리킨다.
- **영향 범위:** CLI 설치, npx 실행, MCP client 등록 시 사용하는 npm package spec.

### B. 사용자 안내와 MCP 설정 예시 동기화
- **관련 위치/대상:** 루트 README, CLI README, `DESIGN.md`, 프런트엔드 MCP 가이드 콘텐츠와 npm 링크
- **변경 전 상황:** 설치 명령, MCP server args, 문제 해결 안내, npm package 링크에 이전 개인 scope가 남아 있었다.
- **변경한 내용:** 모든 현재 사용자 안내와 런타임 MCP 가이드 참조를 `@openloghq/cli`로 교체했다.
- **변경 후 동작:** MCP 가이드에서 복사한 로그인·MCP 명령과 package 링크가 새 공식 패키지로 연결된다.
- **영향 범위:** 영문·한글 README, `/settings/mcp-guide` 화면, CLI 패키지 README.

### C. OpenLog 브랜드 자산 적용
- **관련 위치/대상:** `frontend/public/brand`, 공통 `OpenLogLogo` 컴포넌트, 헤더·랜딩·인증·온보딩·미리보기 UI, 앱 metadata
- **변경 전 상황:** 화면별로 Georgia 텍스트와 검은색 `O` 타일을 조합한 임시 로고를 사용했고, 브라우저 아이콘에는 기본 Vercel 파비콘이 남아 있었다.
- **변경한 내용:** 확정된 OpenLog 워드마크와 마크 PNG를 추가하고, 투명 여백을 일관되게 보정하는 공통 로고 컴포넌트를 만들었다. 넓은 영역에는 워드마크를, 작은 아이콘 영역과 파비콘에는 마크를 사용하도록 교체했다.
- **변경 후 동작:** 헤더와 랜딩 푸터에는 OpenLog 워드마크가 표시되고, 인증·온보딩·워크플로 미리보기와 브라우저 탭에는 새 마크가 표시된다.
- **영향 범위:** 랜딩 페이지, 공통 헤더, 로그인·가입 모달, CLI 로그인, 온보딩, 워크스페이스 미리보기, favicon/apple-touch icon.

## 5. 테스트 및 검증 방법
- **검증 환경:** Node.js 25.2.1, pnpm 10, npm public registry
- **검증한 시나리오:** CLI 단위 테스트와 빌드, npm package dry-run, 공개 package metadata 조회, 배포된 package의 npx 도움말 실행, 프런트엔드 lint와 production build를 확인했다. 웨일 기반 브라우저 검증으로 랜딩 화면의 로고 이미지 로딩, 오류 오버레이, favicon metadata도 확인했다.
- **확인한 결과:** CLI 테스트 18건 성공, CLI build 성공, `npm pack --dry-run` 성공, `npm view @openloghq/cli@latest`에서 `1.1.0` 확인, `npx -y @openloghq/cli@1.1.0 --help` 성공, 프런트엔드 build 성공, lint 오류 0건과 기존 경고 14건을 확인했다. 랜딩 화면에서 새 로고 이미지 3개가 렌더링되고 오류 오버레이 0건, favicon과 apple icon이 새 마크 PNG를 가리키는 것을 확인했다.
- **확인하지 못한 부분:** 새 패키지의 다음 버전을 GitHub Actions에서 자동 배포하는 흐름은 확인하지 않았다. Trusted Publisher 연결을 별도로 설정해야 한다.

## 6. 리뷰어 참고 사항 (선택)
- **리뷰할 때 봐야 할 점:** 기존 `@kitae9999/openlog-cli` 패키지는 호환성을 위해 deprecate하거나 삭제하지 않았다. `_docs/PR/42. hotfix-openlog-cli-1.1.0.md`의 이전 패키지명은 당시 배포 기록이므로 유지했다. 원본 워드마크 PNG의 큰 투명 여백은 공통 컴포넌트에서 표시 영역만 잘라 사용한다.
- **영향 범위:** 새 설치와 안내는 `@openloghq/cli`를 사용하고, 기존 설치 사용자는 이전 package spec을 계속 사용할 수 있다. 화면별 로고 크기는 공통 컴포넌트의 wrapper 크기로 제어한다.
