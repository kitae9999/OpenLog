## 2. 변경 배경 및 목표
- **변경 전 상태:** 사이드바의 Agent Guide 링크는 `agentWorkspaceId` prop이 전달될 때만 렌더링됐고, 이 prop은 Agent Settings 화면에서만 전달됐습니다.
- **문제/필요성:** 다른 화면이나 직접 URL 진입에서는 Agent Guide가 보이지 않아, 사용자가 Dashboard 링크를 통해 Agent Settings에 들어간 뒤에만 사이드바 항목을 볼 수 있었습니다.
- **이번 PR의 목표:** 로그인한 사용자에게 workspace가 있으면 현재 진입 경로와 관계없이 Agent Guide 링크를 일관되게 표시합니다.

---

## 3. 주요 구현 내용 및 동작 방식

### A. 사이드바 workspace 해석
- **관련 위치/대상:** `HomeSidebar`, active workspace selection
- **변경 전 상황:** Agent Guide 링크 표시와 URL 생성이 선택적인 route prop 하나에만 의존했습니다.
- **변경한 내용:** 명시된 Agent Settings workspace, 현재 workspace data, 저장된 active workspace, workspace 목록의 첫 항목 순서로 링크 대상 ID를 해석합니다.
- **변경 후 동작:** Dashboard, Manage 등 어느 화면에서 사이드바를 열어도 workspace가 있으면 Agent Guide가 표시되고 선택된 workspace 설정으로 이동합니다.
- **구현 흐름:**
  1. 저장된 active workspace가 현재 workspace 목록에 존재하는지 검증합니다.
  2. 우선순위에 따라 해석한 workspace ID로 Agent Guide 링크를 렌더링합니다.
- **바뀌는 데이터/상태:** 서버 데이터 변경 없이 사이드바 링크의 표시 여부와 대상 URL만 변경됩니다.
- **영향 범위:** 로그인 사용자의 공통 workspace 사이드바

### B. 직접 진입 회귀 테스트
- **관련 위치/대상:** Agent Settings E2E fixture와 Playwright spec
- **변경 전 상황:** route별 workspace ID 없이 HomeSidebar를 렌더링하는 케이스가 검증되지 않았습니다.
- **변경한 내용:** workspace 목록만 전달한 사이드바에서도 Agent Guide 링크가 노출되고 올바른 URL을 가지는 시나리오를 추가했습니다.
- **변경 후 동작:** 향후 링크가 다시 route prop에 종속되면 E2E가 실패합니다.
- **영향 범위:** Agent Settings Playwright E2E
