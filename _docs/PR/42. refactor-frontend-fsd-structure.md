## 2. 변경 배경 및 목표

- **문제/필요성:** 라우트 전용 화면과 재사용 위젯, 기능 로직, 엔티티 모델의 경계가 드러나지 않아 변경 영향 범위를 파악하기 어렵고 하위 레이어가 상위 레이어를 참조할 가능성이 있었습니다.
- **이번 PR의 목표:** 기존 화면과 데이터 흐름을 유지하면서 코드를 FSD 레이어와 책임별 슬라이스로 분리하고, ESLint로 레이어 의존 방향을 보호합니다.

## 3. 주요 구현 내용 및 동작 방식

### A. 화면과 도메인 책임을 FSD 레이어로 분리
- **관련 위치/대상:** `frontend/src/00_pages`, `frontend/src/01_widgets`, `frontend/src/02_features`, `frontend/src/03_entities/workspace`, `frontend/src/04_shared/config`
- **변경 전 상황:** 약 90개의 파일이 `home-feed/ui`에 집중되어 라우트 화면, 공용 레이아웃, 워크스페이스 API, 사용자 액션과 클라이언트 상태가 동일한 슬라이스에 포함되어 있었습니다.
- **변경한 내용:** 라우트 전용 화면은 `00_pages`, 재사용 가능한 화면 조합은 `01_widgets`, 사용자 액션과 선택·오버라이드 상태는 `02_features`, 워크스페이스 타입과 조회 API는 `03_entities`, 공용 브랜드 설정은 `04_shared`로 이동했습니다.
- **변경 후 동작:** App Router의 `app` 디렉토리는 라우팅과 파라미터 처리만 담당하고 실제 화면은 책임별 슬라이스에서 조합됩니다.
- **구현 흐름:**
  1. `app` 라우트가 `@/pages`, `@/widgets`의 화면 컴포넌트를 불러옵니다.
  2. 화면과 위젯은 필요한 feature 액션 및 entity 모델·API를 참조합니다.
  3. feature와 entity는 상위 화면 레이어를 참조하지 않습니다.
- **영향 범위:** 홈, Activity, Logs, Tasks, Outputs, Memory, Planner, Graph, Workspace 설정 화면과 랜딩·프로필·게시글 화면의 import 경로가 변경됩니다. 사용자 동작과 API 요청 형식은 변경되지 않습니다.

### B. Next.js 경로 충돌 방지와 FSD 의존 규칙 추가
- **관련 위치/대상:** `frontend/tsconfig.json`, `frontend/eslint.config.mjs`
- **변경 전 상황:** pages 레이어 alias가 없었고 FSD 레이어의 역방향 import를 자동으로 차단하는 규칙도 없었습니다.
- **변경한 내용:** Next.js Pages Router로 인식되는 `src/pages`와의 충돌을 피하기 위해 물리 경로를 `src/00_pages`로 두고 `@/pages/*` alias를 추가했습니다. shared, entities, features, widgets별 `no-restricted-imports` 규칙도 추가했습니다.
- **변경 후 동작:** 애플리케이션 코드는 `@/pages/*`로 화면 레이어를 참조하며, 하위 레이어에서 상위 레이어를 import하면 ESLint 오류가 발생합니다.
- **영향 범위:** TypeScript 모듈 해석과 프론트엔드 ESLint 검사에 적용됩니다.

## 4. 스크린샷 (선택)

구조와 import 경로만 변경한 리팩터링으로 화면 변경은 없습니다.

## 5. 테스트 및 검증 방법
- **검증 환경:** Node.js, Next.js 16.1.6, TypeScript 5, ESLint 9
- **검증한 시나리오:** 전체 TypeScript 타입 검사, ESLint 검사, Next.js 프로덕션 빌드, 이동 전후 주석 보존 여부와 FSD 역방향 import를 확인했습니다.
- **확인한 결과:** `npx tsc --noEmit` 통과, `npm run build` 통과, `npm run lint` 오류 0건을 확인했습니다. ESLint 경고 14건은 리팩터링 전과 동일한 기존 Hook 의존성 경고입니다.
- **확인하지 못한 부분:** 브라우저 E2E 테스트는 별도로 실행하지 않았습니다.
