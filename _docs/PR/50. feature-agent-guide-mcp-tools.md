## 2. 변경 배경 및 목표
- **변경 전 상태:** MCP는 `start_openlog_session`으로 Agent Guide를 읽을 수만 있었고, 세션 중 Guide를 수정하는 툴이 없었다. Guide 수정은 웹 UI 또는 REST `PUT /workspaces/{id}/agent-guide`로만 가능했다.
- **문제/필요성:** 사용자가 세션 대화에서 합의한 행동·기록 정책을 Guide에 바로 고정하려면 에이전트가 MCP로 Guide를 갱신할 수 있어야 한다. 일회성 지식(NOTE Log)과 지속 정책(Guide)을 구분하려면 전용 쓰기 툴이 필요하다.
- **이번 PR의 목표:** `get_workspace_agent_guide`와 `update_workspace_agent_guide`(confirm preview)를 MCP에 추가하고, 관련 문서·테스트를 갱신한다.

## 3. 주요 구현 내용 및 동작 방식

### A. Agent Guide MCP 읽기/수정 툴
- **관련 위치/대상:** `packages/openlog-cli/src/mcp-workspace-tools.ts`, `packages/openlog-cli/src/mcp-server.ts`
- **변경 전 상황:** Guide 읽기는 세션 시작 응답에만 포함되었고, 수정 MCP 툴은 없었다.
- **변경한 내용:**
  - `get_workspace_agent_guide` (`read`) → `GET /workspaces/{workspaceId}/agent-guide`
  - `update_workspace_agent_guide` (`write`) → 기본은 preview만 반환, `confirm: true` 또는 `skipConfirmation: true`일 때만 `PUT`
  - MCP instructions에 세션 중 Guide 갱신 가이드 한 줄 추가
- **변경 후 동작:** 에이전트가 최신 Guide를 다시 읽고, 초안 preview 확인 후 Guide 전체를 교체할 수 있다.
- **구현 흐름:**
  1. `get_workspace_agent_guide`로 현재 content/revision 조회
  2. 합의된 정책만 반영한 전체 Markdown으로 `update_workspace_agent_guide` 호출 (미confirm → preview)
  3. 사용자 확인 후 `confirm: true`로 PUT
- **바뀌는 데이터/상태:** workspace Agent Guide `content`, `revision` 증가
- **영향 범위:** OpenLog CLI MCP (`safe-write` 이상), 문서 카탈로그. Backend API 변경 없음.

### B. 테스트·문서
- **관련 위치/대상:** `packages/openlog-cli/test/mcp-server.test.ts`, README, mcpGuideContent
