## 2. 변경 배경 및 목표
- **변경 전 상태:** Backend CD는 `deploy/production/`을 운영 경로에 `rsync --delete`로 동기화하면서 Nginx 인증서만 삭제 대상에서 제외했다.
- **문제/필요성:** OCI 운영 경로에는 최종 DB dump를 보관하는 `backups/`와 GCP에서 OCI로 데이터를 재동기화하는 `migration/`이 함께 있다. 기존 동기화를 실행하면 source에 없는 두 디렉터리가 삭제된다.
- **이번 PR의 목표:** 일반 배포 asset은 기존처럼 동기화하되 OCI 전환과 복구에 필요한 backup 및 migration 파일은 보존한다.

---

## 3. 주요 구현 내용 및 동작 방식

### A. 운영 상태 디렉터리 rsync 제외
- **관련 위치/대상:** `.github/workflows/backend-cd.yml`
- **변경 전 상황:** `rsync --delete --exclude 'nginx/certs/'`만 사용해 `backups/`와 `migration/`이 삭제 대상이었다.
- **변경한 내용:** `backups/`와 `migration/`을 exclude 목록에 추가하고 각 옵션을 별도 줄로 분리했다.
- **변경 후 동작:** Compose, Nginx, Debezium 등의 배포 asset은 계속 최신 상태로 동기화되지만 운영 backup, migration script, TLS 인증서는 유지된다.
- **바뀌는 데이터/상태:** GitHub Actions rsync의 원격 삭제 대상에서 `backups/`, `migration/`, `nginx/certs/`가 제외된다.
- **영향 범위:** Backend CD의 production asset 동기화 단계.
