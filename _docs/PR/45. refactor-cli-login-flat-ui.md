## 2. 변경 배경 및 목표
- **변경 전 상태:** `/cli-login`은 회색 캔버스(`#f8fafc`) 위 흰 카드·그림자로 구성된 승인 화면이었고, OAuth·Approve 버튼도 카드형 크롬을 사용했다.
- **문제/필요성:** 제품 UI가 paper-white flat 문법으로 정리되는 중인데, CLI 로그인 페이지만 이전 SaaS 카드 톤이 남아 시각 언어가 어긋난다.
- **이번 PR의 목표:** CLI 로그인·승인 화면을 워크스페이스 Guest 로그인·flat 에디터와 같은 paper-white 문법으로 맞춘다. 인증/승인 로직은 변경하지 않는다.

## 3. 주요 구현 내용 및 동작 방식

### A. CLI 로그인 페이지 flat 리디자인
- **관련 위치/대상:** `frontend/app/cli-login/page.tsx`, `frontend/app/cli-login/CliLoginApprovalForm.tsx`
- **변경 전 상황:** 카드 셸 + uppercase eyebrow + 박스형 코드/계정 필드 + 큰 filled Approve 버튼
- **변경한 내용:**
  - 카드·그림자·회색 캔버스 제거, `bg-white` 단일 표면
  - 섹션 라벨·underline 코드/계정 필드
  - OAuth를 Guest workspace와 같은 GitHub(primary) / Google(outline) 버튼으로 정렬
  - Approve를 quiet text 액션으로 변경, 에러는 plain rose 텍스트
- **변경 후 동작:** 코드 유효성·로그인/온보딩 분기·승인 API 호출은 동일. UI만 flat 문법에 맞춤.
- **영향 범위:** `/cli-login` 화면(미로그인 / 승인 / invalid code / onboarding incomplete)

## 5. 테스트 및 검증 방법
- **검증 환경:** 로컬 frontend (`next dev` port 3030)
- **검증한 시나리오:**
  1. `http://localhost:3030/cli-login?code=ABCD-2345` 접속 → 페이지 200, flat 레이아웃 렌더
  2. 코드 없는 `/cli-login` → invalid code + quiet Go home 링크
- **확인한 결과:** CLI login 페이지 렌더 성공. (홈 `/`는 백엔드 미기동 시 `ECONNREFUSED`로 500 — 이번 변경과 무관)
- **확인하지 못한 부분:** 실제 OAuth 로그인 후 Approve 성공/실패 플로우(백엔드 device auth 필요)
